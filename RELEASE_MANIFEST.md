# VLMB Music Bot 4.0.0-rc2-postgresql

Architecture & Reliability release candidate built on production 3.0.6.

## Included

- Callback namespace catalog + static callback audit.
- Explicit critical user-flow state machine and regression tests.
- `application/`, `domain/`, `providers/`, and `storage/` boundaries introduced without a flag-day rewrite.
- Unified `MusicProviderAdapter` contract with Yandex/VK/YouTube adapters.
- Adapter-level provider failover tests using the existing circuit-breaker router.
- Deterministic queue/concurrency load smoke test.
- Real deployment rollback drill hook (`FORCE_FAIL_AFTER_CUTOVER=1`) plus isolated rollback test.
- CI from clean checkout through compile, tests, audits, load smoke and rollback drill.
- Existing metrics/provider-health components retained as the observability boundary.
- 3.0.6 UX/favorite fixes preserved.

## Migration status

The 4.0 architecture is an incremental boundary extraction. `music_bot_user_mixes.py` remains the compatibility bootstrap; the full handler/storage extraction is intentionally staged behind tests.

## Production policy

3.0.6 remains the production baseline until CI and the server-side Telegram smoke flow pass for this RC. Keep the pre-release backup until acceptance is complete.

## Security

No `.env`, tokens, databases, logs, virtualenvs, or generated bytecode are included in the release archive.


## PostgreSQL cutover safeguards (rc2)

- Runtime database access is routed through `storage.postgres`; runtime does not fall back to SQLite.
- SQLite source databases are opened read-only by the migration utility and are never deleted.
- SQLite integer columns are widened to PostgreSQL `BIGINT`; auto-increment IDs use `BIGSERIAL`.
- Migration advances a sequence only when the target column actually owns a PostgreSQL sequence.
- SQL placeholder conversion ignores quoted literals and comments.
- PostgreSQL adapter regression tests cover qmark conversion, `INSERT OR IGNORE`, supported `INSERT OR REPLACE` cases, and generated IDs.
- The archive has been syntax-checked and the migration's SQLite dry-run has been exercised locally. A live PostgreSQL integration test and production Telegram smoke test remain required before cutover.
